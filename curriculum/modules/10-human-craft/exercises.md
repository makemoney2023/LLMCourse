# Exercises

## Exercise 1: Turn a vague ask into a one-page spec
**id:** ex-1

Start with a vague request like "Make this better" or "Help with the deck." Rewrite it with outcome, audience, limits, sources, and three done checks.

<details>
<summary>Answer key</summary>

A partner should execute without asking you three more questions. Done checks must be observable.

**Worked example:** Vague: "Fix the email." Spec: Outcome: customer refund reply. Audience: upset buyer. Limits: no new offers. Sources: SOURCES.md policy row. Done: cites policy, under 120 words, plain tone.

</details>

## Exercise 2: Practice reverse questioning
**id:** ex-2

Take a fuzzy ask from your work. Write the instruction that forces **questions only — no draft yet**. List three answers you would give the helper.

<details>
<summary>Answer key</summary>

If the helper drafts anyway, stop it and reinforce the gate. Answer fully before allowing output.

**Worked example:** Fuzzy: "Write about our product." Gate: "Ask five clarifying questions. Do not draft." Answers: audience = dentists; length = 300 words; tone = plain; source = BRIEF.md; no medical claims.

</details>

## Exercise 3: Pick mode and approval rules
**id:** ex-3

For four tasks (email send, brainstorm, prod deploy, typo fix), choose **plan vs go** and whether **approval** is required. Write one reason per choice.

<details>
<summary>Answer key</summary>

High blast radius → plan + approvals. Clear checklist work with low risk → go with light gates.

**Worked example:** Prod deploy → plan mode + approval required (high risk). Typo fix in draft doc → go mode, no approval (low risk, reversible).

</details>

# Exercises

## Exercise 1: Map your last AI chat onto the loop
**id:** ex-1

Think of a real AI chat from this week. Write a short note.
Label steps with: goal, wall rules, desk space, tools, results, check.

Name one time something new landed on the desk.
Name one time you checked the answer—or should have.

<details>
<summary>Answer key</summary>

Name real things, not vague labels.

Worked example — chat: "Draft release notes from this week's tickets."

- Goal: publish accurate release notes for v2.4 by Friday.
- Wall rules: project rules file says "concise, no hype, cite ticket IDs."
- Desk space: changelog paste, three prior release notes, last ten chat turns.
- Tools: none this time (you attached files instead).
- Results: draft bullet list with ticket numbers.
- Check: you opened JIRA and confirmed ticket IDs — one was wrong; you fixed it.

If wall rules or a check step are missing, that is the lesson. Add them before the next draft.

</details>

## Exercise 2: Find waste in a messy ask
**id:** ex-2

Read this messy ask:

> Hey! Write a blog about our API, use this whole 80-page PDF, always use Oxford commas, never mention Competitor X, make it funny but serious, and also research trends. Thanks!!!

List five problems. For each, name the loop stop it hurts and one fix.

<details>
<summary>Answer key</summary>

Too many jobs; huge PDF wastes desk space; style rules belong on the wall; vague tone; research with no source plan; no "done when" check.

Worked example fixes:

1. Too many jobs at once hurts user intent — the ask gets lost. Pick one: "800-word API overview for developers."
2. An 80-page PDF eats up desk space. Attach one short section instead, or a BRIEF.md summary.
3. Style rules like Oxford commas and naming Competitor X don't belong in a one-off chat ask — they hurt standing context. Move them to wall rules instead.
4. "Funny but serious" gives verify nothing to check. Write one tone example, or a before/after pair, instead.
5. "Research trends" with no plan floods the desk with random tool results. Do deep research first, and cite SOURCES.md.

</details>

## Exercise 3: Rewrite a fuzzy ask into a clear goal
**id:** ex-3

Rewrite the messy ask into one clear goal.
Add three "done when" checks.
Say what to put on the desk and what to leave off.

<details>
<summary>Answer key</summary>

Worked example rewrite:

**Goal:** Write an 800-word developer blog post explaining our REST API auth flow for new integrators.

**Done when:**

1. Every endpoint name matches the public docs (check SOURCES.md row 1).
2. Tone is professional with one light humor line max.
3. Competitor X is not named.

**On the desk:** BRIEF.md, auth section excerpt (not full PDF), wall rules for Oxford commas.

**Off the desk:** full 80-page PDF, trend research (do that in a separate research pass first).

One audience, one length, one source, three checks — that is a loop-ready ask.

</details>

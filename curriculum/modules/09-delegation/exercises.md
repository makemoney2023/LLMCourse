# Exercises

## Exercise 1: Split a big job into specialist briefs
**id:** ex-1

Take a mega-task (launch one-pager, feature spec, or event plan). Split it into two specialist jobs. Write one goal line and one out-of-scope line for each. Each job should use different tools or outputs.

<details>
<summary>Answer key</summary>

Each specialist should own different outputs. No shared editable file unless one merge owner holds the lock.

**Worked example:** Job A — Research: gather three competitor prices; out of scope: writing copy. Job B — Writer: draft one-page summary from BRIEF.md only; out of scope: new web research.

</details>

## Exercise 2: Write a delegation contract
**id:** ex-2

Fill a full contract: goal, inputs, allowed tools, out of scope, done checks, return format, merge owner. Use a real or sample task. Done checks must be testable — a teammate can say yes or no.

<details>
<summary>Answer key</summary>

If the merge owner is missing, rewrite until someone owns integration. Done checks must be testable.

**Worked example:** Goal: ten research bullets with links. Inputs: BRIEF.md. Tools: search only. Done: each bullet has URL + date. Return: markdown list. Merge owner: you.

</details>

## Exercise 3: Spot unsafe parallel work
**id:** ex-3

Describe three scenarios where two helpers run at once. Mark each **safe** or **unsafe**. For every unsafe one, write one fix (serialize, split files, or name merge owner).

<details>
<summary>Answer key</summary>

Same file or same rows without a lock → unsafe. Different docs with clear owners → often safe.

**Worked example:** Unsafe: two agents edit `auth.ts` → fix: one editor at a time. Safe: research doc vs outline doc with you as merge owner.

</details>

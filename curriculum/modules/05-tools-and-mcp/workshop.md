# Workshop facilitator notes: Tools & MCP

**Workshop session:** 2  
**Module duration:** ~35 minutes  
**Opens Session 2** after loop recap

## Purpose

Learners see tools as part of the loop—not magic—and leave with a slimmer, clearer tool catalog mindset.

## Timing

| Segment | Minutes | Activity |
|---------|---------|----------|
| Recap | 5 | Session 1 take-homes; loop + standing context refresh. |
| Teach | 10 | Tool cycle demo; MCP as catalog; minimal set principle. |
| Exercise 1 | 8 | Individual inventory; pair compare disable lists. |
| Exercise 2 | 10 | Groups pick workflow; pitch minimal tool set. |
| Exercise 3 | 7 | Rewrite one bad tool description live. |
| Bridge | 5 | Preview Module 5: retrieval as evidence, not noise. |

## Demo steps

1. Enable a read tool (search or file read) and a mutating tool if sandbox allows.
2. Run task requiring read tool; **highlight observation** entering thread.
3. Show a **wrong-tool** example: ambiguous descriptions → model picks web instead of internal search.
4. Optionally show MCP settings page—count schema size as standing context cost.

## Discussion prompts

- "Which of your tools are read vs mutate—and which mutate without approval?"
- "Where do tool descriptions live today—who maintains them?"
- "What would you remove from the catalog without losing your top workflow?"
- "How is MCP different from 'just another plugin'?"

## Safety note

Do not demo destructive tools on production systems. Use sandbox or read-only credentials.

## Materials

- Module diagram (tools + observe highlighted)
- Sample bad tool description for Exercise 3 rewrite
- Whiteboard: Model → Tools → Observe → Window

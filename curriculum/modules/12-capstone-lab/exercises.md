# Exercises

## Exercise 1: Choose and scope your capstone workflow
**id:** ex-1

Name the workflow, the single artifact you will ship, and a time box under 90 minutes. Write one sentence on what you will **not** do in this run.

<details>
<summary>Answer key</summary>

If it needs a week, cut scope. One outcome only. The not-do line prevents scope creep mid-run.

**Worked example:** Workflow: weekly manager status. Artifact: five-bullet note. Time box: 45 minutes. Not doing: slide deck or code changes in this run.

</details>

## Exercise 2: Configure loop artifacts
**id:** ex-2

Before generating anything, list what you will create or update: BRIEF.md, SOURCES.md, wall rules, one playbook, tool allow list, and verify checklist. Draft at least two lines for each.

<details>
<summary>Answer key</summary>

All six pieces should exist, even if short. Facts stay in the pack, not in huge wall text. Configure through Module 11 before you run.

**Worked example:** BRIEF.md: goal + owners. SOURCES.md: three ticket links with dates. Wall: plain tone. Recipe: status spec. Tools: search + attach only. Verify: five done checks written.

</details>

## Exercise 3: Run, measure, and write a look-back
**id:** ex-3

Run your capstone once. Record one metric (time, revisions, or errors caught). Write a look-back: what improved, what failed first, and one team default to keep.

<details>
<summary>Answer key</summary>

Strong look-backs name a metric and one durable default — a rule, checklist, or pack habit — not vague praise.

**Worked example:** Metric: 18 min vs old 28 min; zero source errors. Failed first: none. Default: always attach BRIEF.md before status drafts; share verify checklist with desk.

</details>

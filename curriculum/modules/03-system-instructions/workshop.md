# Workshop facilitator notes: System instructions

**Workshop session:** 1  
**Module duration:** ~30 minutes  
**Prerequisites in session:** Mental model (Module 1)

## Purpose

Learners audit real standing instructions, practice altitude, and resolve conflicts before adding playbooks in Module 4.

## Timing

| Segment | Minutes | Activity |
|---------|---------|----------|
| Recap | 2 | Link standing context node to "invisible every-turn bias." |
| Teach | 8 | Altitude table + conflict layers diagram on whiteboard. |
| Exercise 2 | 8 | Individual rewrite of bloated block (lesson); pairs compare diffs. |
| Exercise 3 | 7 | Small groups resolve A/B conflict; share precedence patterns. |
| Exercise 1 | 5 | Start personal audit; finish as homework if needed. |
| Bridge | 3 | Preview Module 4: rules vs on-demand skills. |

## Demo steps

1. Show a **before/after** instruction block (use lesson Exercise 2 bloated version → rewrite).
2. Run the **same user prompt** in two configs if feasible: bloated vs lean (or describe expected diff if live compare is slow).
3. Show a **conflict example**: add contradictory rules to a test project; run standard prompt; highlight inconsistent behavior.
4. Point to where each product stores instructions (portable mapping table)—learners locate their own.

## Discussion prompts

- "Which of your rules are actually **defaults** you could drop when the user specifies otherwise?"
- "What did you move out of system instructions into retrieval?"
- "Who owns team standing instructions today—is there a review process?"
- "How would you test that a change worked?"

## Facilitation notes

- Normalize redaction: learners may not share screen; pair discussion is enough.
- Push back on **paste-the-whole-employee-handbook** instinct.
- Connect to Module 1: bloated standing context steals budget from tool results later.

## Materials

- Module `diagram.mmd` (standing context highlighted)
- Printed bloated instruction block for Exercise 2
- Optional: team template for "instruction regression prompt"

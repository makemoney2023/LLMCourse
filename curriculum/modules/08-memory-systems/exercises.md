# Exercises

## Exercise 1: Sort ten facts by memory place
**id:** ex-1

List ten facts about a project you know. Sort each into **desk only**, **binder note**, **product memory**, or **never store**. Write one sentence why for each.

If you need a starter set, use these ten and sort them:

1. Today's draft reply wording
2. Support email for the product
3. Staging API key pasted in chat
4. "Launch is March 12" (never verified)
5. Prefer plain language, no hype
6. Full 40-row pricing table
7. Owner of BRIEF.md this quarter
8. Rejected joke opener from yesterday
9. Refund window from last year's sticky
10. Team Slack channel name

<details>
<summary>Answer key</summary>

Secrets never get saved. Today's hypothesis stays on the desk only. A stable process belongs in the binder or on the wall. A light preference can go in product memory, if you save it at all.

**Worked example:**

| Fact | Place | Why |
|------|-------|-----|
| Draft reply wording | Desk only | One-session scratch |
| Support email | Binder | Team needs one auditable home |
| Staging API key | Never store | Rotate; use a vault |
| Unverified launch date | Desk only until confirmed | Then BRIEF.md with a date |
| Plain language preference | Product memory | Light, stable preference |
| Pricing table | Binder via SOURCES.md link | Too big for stickies |
| BRIEF.md owner | Binder | Ownership is team truth |
| Rejected joke opener | Desk only / delete | Do not promote rejected drafts |
| Last year's refund sticky | Prune | Stale; replace with dated SOURCES.md |
| Slack channel name | Binder or wall | Stable team fact |

</details>

## Exercise 2: Draft a project note template
**id:** ex-2

Make a tiny binder template with Goal, Owners, Links, Do not, and Open questions. Fill it with real or sample content in under ten lines. A new teammate should read it on Monday and start work without a long re-brief.

<details>
<summary>Answer key</summary>

If it replaces re-explaining the project each Monday, it works. Link to SOURCES.md instead of pasting long policy text.

**Worked example:**

```
# Support FAQ bot — binder note
Goal: ship five grounded FAQ answers for clinic partners.
Owners: Sam (content), Lee (tools).
Links: BRIEF.md · SOURCES.md#refund · HANDOFF.md template.
Do not: medical claims; invent phone numbers; store API keys in chat memory.
Open questions: weekend support hours (ops); tone sign-off (legal).
```

</details>

## Exercise 3: Prune a noisy memory list
**id:** ex-3

Write five sample memory stickies — include at least one stale, one conflicting, and one secret-like item. Cross out three bad ones. Rewrite one dated fact correctly.

<details>
<summary>Answer key</summary>

Delete conflicts and undated folklore. Keep dated, useful stickies. Never keep secrets in memory.

**Worked example stickies:**

1. ~~Pricing is $9~~ (undated, wrong)
2. ~~Password: test123~~ (secret — never store)
3. ~~Be playful always~~ (conflicts with current wall: plain tone)
4. Prefer plain language, no hype (keep)
5. Rewrite: "Refund window 5–7 business days as of 2026-07-21 — see SOURCES.md row 3."

</details>

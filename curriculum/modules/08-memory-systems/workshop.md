# Workshop facilitator notes: Memory systems

**Workshop session:** 3  
**Module duration:** ~30 minutes  
**Follows:** Conversation & compaction in same session

## Purpose

Learners classify facts by memory tier, draft a project note template, and practice pruning—reducing repetition without poisoning future sessions.

## Timing

| Segment | Minutes | Activity |
|---------|---------|----------|
| Teach | 8 | Three tiers table; memory vs retrieval vs instructions. |
| Exercise 1 | 8 | Classify ten facts; pairs compare borderline cases. |
| Exercise 2 | 10 | Draft project memory template; gallery walk. |
| Exercise 3 | 7 | Audit noisy list—emphasize secret deletion. |
| Bridge | 2 | Preview delegation: what memory should **not** carry into parallel agents. |

## Demo steps

1. Show product memory UI or a sample `AGENTS.md`—contrast opacity vs repo doc.
2. Walk one fact (fiscal year) through wrong tier—stale in memory vs linked doc.
3. Red-team: "remember our DB password"—delete, rotate, team rule.
4. Optional: two teammates with different personal memory—same task, different outputs.

## Discussion prompts

- "What do you currently re-explain every session?"
- "Where is team truth stored—and can you PR it?"
- "What should never enter product memory?"
- "How does your handoff template (Module 7) feed external notes?"

## Session 3 synthesis

After Module 8: working context (Module 7 compaction), durable memory (Module 8), parallel windows next (Module 9)—three ways context scales beyond one thread.

## Materials

- Module diagram (memory → window path highlighted)
- Sample noisy memory list (Exercise 3) on slide
- Blank project note template starter (optional handout)

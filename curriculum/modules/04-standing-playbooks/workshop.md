# Workshop facilitator notes: Standing playbooks

**Workshop session:** 2  
**Module duration:** ~35 minutes  
**Opens Session 2** after Session 1 pack recap

## Purpose

Learners split guidelines into always-on vs on-demand and leave with artifacts they can use Monday.

## Timing

| Segment | Minutes | Activity |
|---------|---------|----------|
| Recap | 5 | Collect BRIEF.md / SOURCES.md from Session 1. |
| Teach | 8 | Rules vs skills decision checklist; overload demo. |
| Exercise 1 | 10 | Group sort of ten items; debate borderline cases. |
| Exercise 2 | 8 | Draft one always-on rule; neighbor review for testability. |
| Exercise 3 | 12 | Draft one playbook; share triggers aloud. |
| Bridge | 5 | Preview Module 5: tools enter the loop. |

## Demo steps

1. Open a project with bloated always-on rules (anonymized example or facilitator's own).
2. Show context indicator or estimate token cost if available.
3. **Demote** one long procedure from always-on to linked playbook in live edit.
4. Invoke playbook on matching task; show lean standing context on non-matching task.

## Discussion prompts

- "What did you demote from always-on today?"
- "How will teammates discover your playbook trigger?"
- "What happens if two playbooks trigger on the same message?"
- "How does this connect to system instructions from Module 3—duplicate or complement?"

## Session 2 opening synthesis

Tie back to loop: standing context now has **two speeds**—hot rules and triggered playbooks. Next: tools and retrieval enter from the model side of the loop.

## Materials

- Cards or slide with ten guidelines (Exercise 1)
- Template: Trigger / Inputs / Steps / Done / Anti-pattern
- Module diagram (standing context highlighted)
